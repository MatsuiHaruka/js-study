## 使い方

問題2.6について、解答コードの作成は依頼せず、エラーの原因説明・デバッグの方向付け・言語機能（`Array.from`、三項演算子、アロー関数の式本体）の説明を目的にAIを利用した。実装・修正はすべて自分で行った。

やり取りの経過は以下のとおり。

1. `export class FizzBuzz{` の直下に `for` 文を書いてパースエラーになった原因（クラス本体にはメソッド/フィールド定義しか書けず、文をそのまま置けないこと）と、そもそも課題が「1行で文字列を返す関数」を求めており `class`／`console.log` では要件と合っていないことの説明を受けた。
2. クラスを外して `for` 文だけにした結果 `fizzbuzz is not a function` になった原因（`fizzbuzz`という名前でexportされた関数が存在しないこと、`console.log`ではなく`return`で文字列を返す必要があること）の説明を受けた。
3. 最初の関数実装（`class`ベース、`Array.prototype.map()`を要素追加のつもりで誤用、`return`がループ内、`"FissBuzz"`のタイポ）について、それぞれの原因（`map`は要素変換であり追加ではないこと、`return`の位置、タイポ）の指摘を受けた。
4. `unshift()`を使ったことで結果が降順になる原因の説明を受けた。
5. `push()`に直し`return console.log(num.join("\n"))`とした際、`console.log`の戻り値が`undefined`であるため文字列を返せていない点の指摘を受けた。
6. テスト失敗の差分（末尾の改行1つ分の不一致）を見て、`join("\n")`が要素の「間」にしか改行を入れないため末尾の改行が足りないことの説明を受けた。
7. `num.push("\n")`で末尾改行を試みた際、配列要素として追加した`"\n"`と`join`の区切り文字の`"\n"`が両方入り改行が2つになってしまう理由の説明を受け、`num.join("\n") + "\n"`という形に自分で直したところテストが通った。
8. 「1行で書く」という要件を満たすため、`for`文を`Array.from`に置き換える方針（`Array.from({length: n}, コールバック)`の第1引数・第2引数の意味、コールバックの`index`が0始まりであること、`_`が「使わない引数」を表す慣習であることなど）を、`Array.from({length: 5}, (_, index) => index * 2)`という別例を使って説明してもらった。
9. 書き換えの過程で生じた複数のエラー（`(_, index+1)`のように引数部分に式を書いてしまい構文エラーになったこと、本体中の`i`を`index + 1`に置き換え忘れていたこと、`num + "\n"`が配列を暗黙にカンマ区切り文字列へ変換してしまうため`join`が必要なこと）について、その都度原因の指摘を受けて自分で修正した。
10. `Array.from(...).join("\n") + "\n";`を関数本体の`{ }`内にそのまま書いただけでは`return`がなく`undefined`が返ってしまう点の指摘を受け、`{ }`と`return`を外してアロー関数を式本体にすることで1行化し、最終的にテストが通った。
11. 「1行」という制約の意図（`for`/`if`のような命令文ではなく`map`/`Array.from`/三項演算子といった式で処理を組み立てる練習という一般的な位置づけ）について説明を受けた。
