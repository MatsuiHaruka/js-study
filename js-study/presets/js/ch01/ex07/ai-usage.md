## 使い方

`add` メソッドの実装について、コード自体を書いてもらうのではなく、詰まった箇所ごとに**ヒント・質問形式**で教えてもらった。実装は自分で書いた。

やり取りの流れ（概要）:

1. 「自分の座標」と「引数で渡されたインスタンスの座標」の違いが分からず質問 → `this` はメソッドを呼び出したオブジェクトを指す、という考え方を、Pointクラスとは別の簡単な例（`obj1.greet()` / `obj2.greet()`）で確認した。
2. `add()` に引数がなかった点を指摘され、なぜ引数（`other`）が必要か、`function double(n)` のような最小の例で「引数は呼び出し時に値が入る箱」であることを確認した。
3. `return (this.x, this.y)` のように書いて詰まった際、カンマ演算子は最後の値しか返さないことを、`sample.js` で実際に実行して確認した。
4. 「2つの値（x, y）をどう1つの `return` にまとめるか」で詰まり、`constructor` と `new Point(...)` のパターンを思い出すヒントをもらい、`new Point(newX, newY)` を返す形にたどり着いた。
5. `return p(newX, newY)` のように書いてしまい（`p` を関数として呼び出そうとしていた）、変数の中身をそのまま返せばよいことを指摘された。

## 自分で書いた部分

- `add(other)` の引数定義
- `newX`, `newY` の加算処理
- `new Point(newX, newY)` で新しいインスタンスを作り `return` する処理
- 呼び出し側 (`p.add(other)`) の記述

## 使い方

`index.test.js` のテストコードについて、書き方の間違いをヒント・質問形式で指摘してもらった。テストコード自体は自分で書いた。

やり取りの流れ（概要）:

1. 最初に書いていた `expect(2, 3).toBe(2, 3)` について、`expect()` / `toBe()` はどちらも第1引数しか見ないこと、そもそも `Point` クラスを一切使っていないテストになっていることを指摘された。
2. `p.add(other)` の結果を `toBe(4, 6)` と比較していた点について、`toBe` はオブジェクトの中身ではなく同一性（参照）を見る仕組みだと説明を受け、`toEqual` や `.x`/`.y` を個別に比較する方法があることを教わった。
3. `index.js` に空の `point()` 関数や、決め打ちの値を使う `addPoint()` を追加していた際、関数とクラスの違い、および「メソッドごとに専用のexport関数を増やす」より「`Point` クラス自体をexportする」方が、テスト側で自由にインスタンスを作れて拡張性が高いことを、比較質問形式で気づかせてもらった。
4. `export` と `constructor` を混同していた点について、それぞれ別の役割（外部公開 / インスタンス初期化）であることを、別クラスの最小例で確認した。
5. `expect(new Point(0, 0)).toBe(0)` のように、Pointインスタンスそのものと数値を比較していた点を指摘され、`.distance()` を呼んだ結果を比較する必要があることに気づいた。
6. `distance()` の期待値に長い小数（`6.708203932499369`）を直書きしていた点について、可読性の観点から `Math.sqrt(...)` で式のまま書く方法と、ピタゴラス数（3-4-5）を使ってキリの良い整数にする方法を提案された。

## 自分で書いた部分

- テストケースの内容（`describe`/`it` の構成、アサーションの選択）すべて
- `Point` クラスへの `export` の追加
- `distance()` テストの座標選定（`(0,0)`, `(3,4)`）
- `add()` テストの `toEqual` / `.x`・`.y` 個別比較、両方の実装

## AIが直接書いたコード

なし。最終的なテストコードはすべて自分で記述し、`npx vitest run` で6件のテストが通ることを確認済み。
