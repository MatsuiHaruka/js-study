# AI 利用記録 (ex13)

## 使い方

`eq` / `lte` の実装中、自分で書いたコードが期待通りに動かないときに Claude Code (claude-sonnet-5) に相談しながら進めた。AI に解答をそのまま書いてもらうのではなく、以下のような形で利用した。

- 自分が書いたコードの意図と実際の挙動のズレを指摘してもらう
- `npx vitest run` やテスト内容をもとに、どのテストケースが失敗しているか具体的に洗い出してもらう
- `console.log` や Node での検証コードを一緒に実行して、`typeof null` や `Date` の変換順序など、JS の仕様の癖を確認する
- 次に何を直すべきかヒント・質問の形で示してもらい、実際のコード修正は自分で行う（AI が完成コードを書くことはしていない）


## 主な気づき（JS の仕様に関するもの）

- `typeof null === "object"` という仕様の癖。`null` を object 判定ロジックの中で誤って数値変換してしまうバグの原因になった。
- `eq`（`==`）では `null`/`undefined` は「お互いにだけ true」という特別ルールだが、`lte`（`<=`）では `null` は `0` として扱われ、`undefined` は `NaN` が絡んで常に `false` になる、という違いがある。
- オブジェクト同士（例: 自作クラスの別インスタンス同士）を比較するときは `valueOf`/`Number()` 変換をせず、参照比較のままにする必要がある。
- `Date` オブジェクトは他のオブジェクトと違い、`==` の際に `valueOf`（数値）より `toString`（文字列）を優先して変換するという特別ルールがある（Node で `date == date.toString()` などを検証して確認した）。
- `<=` で文字列同士を `Number()` に変換すると `NaN <= NaN` が常に `false` になり、辞書順比較の結果と食い違う。文字列同士はそのまま `<` を使う必要がある。

## 最終結果

`npx vitest run` で `index.test.js` の全120件（`eq` 72件、`lte` 48件）がパスすることを確認した。
