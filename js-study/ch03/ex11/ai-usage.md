## 使い方

オブジェクトの可変性・参照比較、および `equals` 関数の実装について、コードを書いてもらうのではなく、**ヒント・質問形式**で考え方を教えてもらった。実装・テストコードは自分で書いた。

やり取りの流れ（概要）:

1. `const obj1 = { x: 1 };` に対して `obj1 = { x: 1, y: 2 };` と再代入するコードを書いたところ、`const` は再代入を禁止するだけで中身のプロパティ変更は可能であることを指摘され、`obj1.y = 2;` のようなプロパティ代入の書き方をヒントとして教えてもらった。
2. プロパティ名（オブジェクトリテラルの `キー`）の意味と、ドット記法でのアクセス方法を、汎用的な例で説明してもらった。
3. `obj1.y = 2;` を書くつもりが打ち間違いで `obj1, (y = 2);` となってしまい（`.` と `,` の入力ミス）、カンマ演算子として解釈されて意図通りに動かないことを指摘してもらった。
4. `equals` 関数の自力実装をレビューしてもらい、以下の指摘を受けた。
   - `typeof o1 !== "object"` だけでは `null` を弾けない（`typeof null === "object"` のため）。
   - `o1 !== o2` でプロパティの数・名前を判定しようとしていたが、これは常に `true` になり意図した比較になっていない。
   - 配列的な `for (let i = 0; i < o1.length; i++)` のループはオブジェクトの `length` が `undefined` のため機能しない。
   - `Object.keys()` で配列同士を `!==`（参照比較）で比べても常に不一致になってしまうこと、`equals(o1 === o2)` のように引数を1つだけ渡すと無限再帰になること、`.every()` の第2引数は比較用の配列ではなく `thisArg` であることなど、複数回の実装ミスをその都度指摘してもらった。
   - 最終的に `key in o2` と `equals(o1[key], o2[key])` を使った `.every()` による名前比較・値の再帰比較の構文を、汎用的な例（`a`, `b` という別変数）で教えてもらい、自分のコードに反映した。
5. `index.test.js` について、`test(...)` の中に `it(...)` をネストして書いてしまい失敗した際、`test`/`it` は同じ関数のエイリアスであり、複数のテストをまとめるには `describe` を使う必要があると指摘された。
6. 最終的に `npm test` で7件のテストがすべて通ることを確認した。
